# 5. 性能

图标库会被大量、高频使用，性能是硬指标。这页说明性能目标、做法和验证方式。

状态：设计目标，**尚未实测**。所有数字是待验证的目标值，不是已有结论。

## 5.1 性能要求

典型场景：

| 场景               | 规模                   |
| ------------------ | ---------------------- |
| 工具栏、菜单       | 几十个图标             |
| 表格、树、文件列表 | 几百到几千个单元格图标 |
| 图标选择器         | 上千个图标同屏滚动     |
| 加载动画           | 几十个同时旋转         |

**最低要求：列表滚动不掉帧。** 一帧 16 毫秒内要画完所有可见图标，所以单个图标的绘制必须是微秒级。

## 5.2 三条硬规则

### 一、绘制路径里不许有慢操作

`paint` 被调用时只能做一件事：**把已经准备好的图画上去。**

禁止出现在绘制路径里：

- 网络请求
- 读写磁盘
- 解析 JSON
- 解析、渲染 SVG
- 加锁等待

这些全部提前做好或放后台。绘制时拿不到数据就画空白，不要等。

### 二、同样的东西只算一次

同一个图标在界面上出现 100 次，应该：

- 图标数据**只解析一次**
- 相同参数的位图**只渲染一次**
- 需要下载时**只请求一次**

### 三、不做无用功

- 图标不可见时不渲染
- 动画在窗口最小化时暂停
- 参数没变就不重新生成

## 5.3 分三层缓存

```text
图标数据缓存   ← 解析后的图标定义，一个图标一份
     ↓
SVG 文本缓存   ← 应用颜色、变换后的 SVG
     ↓
位图缓存       ← 最终画到屏幕上的图，按尺寸和缩放比分开
```

为什么分三层：**改颜色不用重新解析数据，改大小不用重新生成 SVG 文本**（只有位图要重画）。每层只在自己那层的输入变化时失效。

### 位图缓存的键

必须包含所有影响画面的因素：

```text
图标名 + 数据版本 + 尺寸 + 屏幕缩放比 + 颜色 + 透明度 + 旋转 + 翻转 + 状态
```

**漏掉任何一项都会出现「改了没反应」或「跨屏还是旧图」。** 这类 bug 很难查，键的设计一次做对。

### 容量控制

| 缓存     | 上限                        | 淘汰 |
| -------- | --------------------------- | ---- |
| 图标数据 | 按条数，默认 1000           | LRU  |
| SVG 文本 | 按条数，默认 500            | LRU  |
| 位图     | **按实际内存**，默认 32 MiB | LRU  |

位图必须按内存算而不是按条数：一个 512×512 的图标占的内存是 16×16 的 1000 倍，按条数算会爆内存。

上限可调：

```python
from pyside_iconify import set_cache_limits

set_cache_limits(pixmap_mib=64, data_entries=2000)
```

## 5.4 大量图标的场景

### 表格、列表

几千行的表格里，**实际可见的只有几十行**。

- Qt 的视图只会为可见项请求图标，我们不用自己做虚拟化
- 但要保证**滚动时命中缓存**：同一个图标在不同行用相同参数，键一致就只渲染一次
- 相同图标的不同行共用同一个位图，不复制

### 图标选择器（上千个不同图标）

这是最极端的场景，每个图标都不一样，缓存命中率低。

对策：

- 按可见区域批量加载数据，不是一个个请求
- 预览用小尺寸，滚动停止后再渲染精细图
- 缓存上限按内存控制，超了就淘汰最久没用的

**这个场景会单独做压测。**

### 动画

几十个图标同时旋转时：

- **所有动画共用一个定时器**，不是每个图标一个
- 默认 60 帧，可降到 30 帧
- 不可见的图标跳过重绘
- 旋转角度量化到固定步进（如 5 度），让位图缓存能复用，不是每帧都重新渲染

最后一条很关键：**不量化的话每帧都是新角度，缓存完全失效。**

## 5.5 启动速度

`import pyside_iconify` 应该很快。

- 导入时**不加载任何图标数据**
- 导入时**不创建 Qt 对象**、不建定时器、不起网络
- 内置占位图用代码画，不读文件

目标：导入耗时在毫秒级，不随图标集合规模变化。

## 5.6 内存

- 图标数据用不可变对象，多处引用同一份，不复制
- SVG 文本用完即弃，只缓存热点
- 位图缓存有内存上限，可配置
- 缓存项不持有 Qt 控件的强引用，避免拖住控件不释放

**长时间运行不应该持续涨内存。** 会做长跑测试验证。

## 5.7 性能目标

待验证的目标值：

| 项目                    | 目标             |
| ----------------------- | ---------------- |
| 缓存命中时取图标        | < 10 微秒        |
| 首次渲染一个 24px 图标  | < 1 毫秒         |
| 解析一个图标的数据      | < 100 微秒       |
| 1000 个图标的列表滚动   | 不掉帧（60 fps） |
| 50 个图标同时旋转       | CPU 占用 < 5%    |
| `import pyside_iconify` | < 50 毫秒        |
| 空闲内存占用            | < 5 MiB          |

**这些是目标，不是实测结果。** Step 4 会逐项测量并更新这张表，做不到的会如实标注。

## 5.8 怎么测

### 基准测试

`tests/benchmark/` 下写可重复运行的脚本，测：

- 缓存命中 / 未命中的取图标耗时
- 不同尺寸的渲染耗时
- 大列表滚动的帧率
- 动画的 CPU 占用
- 长时间运行的内存曲线

### 防止性能退化

把关键指标加进 CI，**明显变慢就让构建失败**。性能退化往往是一点点累积的，靠人工发现太晚。

### 真机验证

自动化测不出来的，手动验证：

- Windows 高分屏滚动是否跟手
- 主题切换时会不会卡一下
- 窗口最小化后 CPU 是否真的降下来

## 5.9 不为性能牺牲的东西

性能重要，但这几条不让步：

- **不为了快而缓存错误结果。** 键该复杂就复杂。
- **不为了快而在绘制里偷偷做慢操作。** 宁可先画空白。
- **不为了省内存而每次重新渲染。** 该缓存就缓存，内存有上限就够了。
- **不做过早优化。** 先测出来慢在哪，再针对性改。

最后一条尤其重要：**先有测量，再有优化。** 拍脑袋优化往往改错地方，还让代码变难懂。
